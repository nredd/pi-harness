- Group the run-settle `in_progress` report by why each todo is open, `owner agent failed or stopped`, `held by the parent`, `blocked` and `agent running`. A todo counts as `blocked` only on a live dependency (`in_progress` and not abandoned, or `pending` with a running owner agent whose completion notice is verified); one whose open blockers are all `deferred`, unowned or abandoned is `held`. An `Agent`-tool background spawn heard at `subagents:created` shows `queued` and counts with `agent running` until it starts; a queued resume includes the preceding settle and a new queue sequence, so it is shown as queued without letting a stale `created` overwrite a later state. Abandoned and parent-held work warns on every settle; a report where everything waits on a running agent or a live dependency is info and shown once until a todo's group, owner, owner agent state or blockers change, or a person prompts. Each displayed todo names its owner alongside any blocker details, including free-text owners with no agent state. Running or queued owners without an explicitly verified completion notice warn rather than suppressing repeated reports; foreground handoffs carry their run identity to update eligibility safely. The armed clause now reads `armed: no todo-owned wake (agent notices list session wakes; unlinked monitors arm no todo)` so it no longer reads as nothing being armed ([#448](https://github.com/nredd/pi-harness/issues/448)).
