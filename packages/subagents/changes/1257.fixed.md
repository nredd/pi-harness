- **Workflows stop cleanly at session end ([#1257](https://github.com/nredd/pi-harness/issues/1257)).** Ending a session waits up to three seconds for each stopped workflow's worker thread and completion handling instead of letting the run settle afterwards and arm a notice timer on the closed queue; a run still going at that deadline has its late completion discarded. No notice is sent while shutdown waits, new launches through the `SubagentWorkflow` tool or `--subagents-workflow-file` are refused meanwhile, and overlapping shutdown events tear down once. A tool-launched run in a file-backed session now keeps its `Stopped` notice for the session you left on `/new`, `/resume`, `/fork` or `/reload` (an addition following the held-notice policy) and drops it on quit; a `--subagents-workflow-file` run still records its entry and queues its `workflow-result` before shutdown returns, quit included.
