- **Subagent transcripts have one writer at a time on a single host and PID namespace ([#1247](https://github.com/nredd/pi-harness/issues/1247)).** Every run that writes a persisted child transcript (spawn, in-process resume, restart reopen) holds an exclusive `<transcript>.writer` claim until it settles, published atomically so a failed write leaves no partial claim (created in place on volumes without hard links, such as exFAT), and writes the canonical path the claim covers, so a session-directory link retargeted mid-run cannot move its writes. A transcript another live process writes is refused as in use, even when that process has been idle past the 120-second write window, and a startup lookup reports it as possibly running. A crashed writer's claim is taken over automatically only on Linux, when its pid is verifiably gone on this host and in the same PID namespace and boot; on macOS and Windows it must be removed by hand (the refusal names the file). Another host or namespace, a live or reused pid, an unreadable claim (a link, FIFO, non-regular or oversized file), a leftover takeover lock or a hard-linked transcript refuses and names what to remove. Not covered yet (legacy unclaimed transcripts, per-record ownership, descriptor-bound opens): [#1347](https://github.com/nredd/pi-harness/issues/1347).
