- **Preserve worktrees when cleanup fails ([#485](https://github.com/nredd/pi-harness/issues/485)).** A failed preservation commit could delete uncommitted work, and a failed removal could hide the surviving path. Cleanup now retains and reports the worktree and error; a successfully created branch is reported too. A clean worktree with populated submodules is still removed; any nested repository (a registered submodule, a gitlink without `.gitmodules`, or a leftover repository in the worktree's `modules` dir) holding uncommitted or unpublished work keeps the worktree and reports it. Untracked files are always counted, even with `status.showUntrackedFiles=no`; commits held only by a tag count as unpublished; nested clones under gitignored paths are inspected, recursively (inside submodules and other ignored clones); `submodule.<name>.ignore` / `diff.ignoreSubmodules` cannot hide a moved gitlink, and a gitlink `git add -A` cannot stage keeps the worktree with an explicit error; and a deinitialized submodule pinned to a sha-fetched commit no longer reads as lost work.
