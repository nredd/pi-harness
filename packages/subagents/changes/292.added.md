- **Settling with agents still running is reported ([#292](https://github.com/nredd/pi-harness/issues/292)).** When a run settles while the session's own agents are running or queued, the parent shows the count and what is armed to wake it, e.g. `Run ended with 3 agents running or queued, armed: 2 agent completion notices wake the parent; 1 foreground or RPC-spawned agent will not`. A background agent's completion notice (`Agent` with `run_in_background`, `@handle` mentions, scheduled jobs) starts a parent turn in every join mode; a foreground agent or an RPC spawn without `isBackground` is marked consumed at settle and notifies nobody, so a stop with only those pending is a warning, `armed: no agent completion notice wakes the parent`. The wording covers agents only, so it never contradicts an armed monitor. A notice is spooled across a session switch and can be dropped when `pi -p` tears down. Nested and workflow children are not counted.
