- **A queued agent stopped before it starts emits `subagents:failed` ([#448](https://github.com/nredd/pi-harness/issues/448)).** `stop_subagent`, `/agents` stop, a session switch (`detach`) or quit (`abortAll`) dropped a still-queued top-level agent with no lifecycle event, so a listener that heard its `subagents:created` (pi-todo's owner state, the `/goal` subagent tracker) saw it queued forever. It now gets `subagents:failed` with `status: "stopped"` and the usual payload, from a new `AgentManager` `onQueuedStop` callback; still no completion notice, since the agent never ran. A queued background resume's `subagents:created` also binds its preceding settle and new queue sequence, so listeners can recognize the resume without accepting stale announcements. Lifecycle events report completion-notice eligibility, and foreground handoffs carry a run identity so listeners do not mistake silent foreground or RPC work for a parent wake.
