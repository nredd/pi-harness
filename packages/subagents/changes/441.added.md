- **Completion notices carry the whole result ([#441](https://github.com/nredd/pi-harness/issues/441)).** A background notice held a 500-char preview (300 per `group` member), so nearly every background agent cost a `get_subagent_result` round trip. It now carries the result, or a failed agent's error and partial output, up to `notificationResultChars` per agent (default `16000`, `/agents` -> Settings -> Notice result chars), keeping head and tail around a marker that names the transcript and `get_subagent_result` past it. Notices sent together share four caps, split so short results stay whole. A result delivered whole is marked read and gets the shorter read retention, except a failure (`error`/`aborted`), which stays unacknowledged in FleetView. Survivors spooled across a session switch are clipped at delivery against the same budget. Each `<result>` is XML-escaped and preceded by a `<result-note>` framing it as subagent output to evaluate, not instructions. The rendered box keeps its preview; `0` restores the old notice.
