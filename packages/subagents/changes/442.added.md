- **`steer_subagent` resumes a finished agent ([#442](https://github.com/nredd/pi-harness/issues/442)).** It used to refuse with `Cannot steer a finished agent`, so the model had to know to switch to `Agent` `resume` with a different parameter set. Like Claude Code's `SendMessage`, one tool now covers both: a `completed`, `steered`, `aborted` or `error` agent is resumed through the `Agent` tool's own background `resume` path with the message as its next prompt, history kept, completion notice to follow, and an evicted agent's persisted session reopened under a new id the old id resolves to. An agent the user stopped is refused. A `resume` or steer that finds only an in-memory eviction note now says `Cannot resume agent "<id>": no saved session is left to reopen.` ahead of the note. An evicted nested or workflow child no longer leaves an eviction note, so `get_subagent_result` and `steer_subagent` keep answering `Agent not found` for it instead of its description and transcript.
