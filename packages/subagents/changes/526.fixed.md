- **`docs/rpc.md` covers a queued RPC spawn's own `signal` ([#526](https://github.com/nredd/pi-harness/issues/526)).** Aborting it is one more queued-stop trigger (one `subagents:failed`, `stopped`). A signal already aborted when the spawn would queue returns an id whose record is already `stopped` and emits no event at all, so a caller resolving on `failed` must check the record or not pass it. Both are now pinned in `test/rpc-lifecycle-gating.test.ts`.
