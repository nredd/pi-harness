- Tag export refusals that only the owner can resolve (clock behind, unreadable or over-budget published history, missing manifest, narrowed or unknown harness set, invalid export state) with a stable code: the CLI ends stderr with one `pi-stats-refusal: {"code":...}` line and library callers get `ExportRefusal.refusal`, so a scheduled sync can stop retrying them; an invalid export state file is now reported by path and fixed reason, never by a JSON parse message that could quote its salt; transient I/O errors on published history stay unclassified and retryable, a refusal keeps its code when the lock release also fails, and the CLI escapes control characters in the diagnostic so a path cannot forge the refusal line ([#1253](https://github.com/nredd/pi-harness/issues/1253)).
