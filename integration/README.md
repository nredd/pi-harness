# Assembled-stack gate

- `integration/stacks/personal.json` is promoted only through the attested `stack/<sha>` snapshot release contract in [`docs/stack-promotion.md`](../docs/stack-promotion.md); this gate supplies its registry-byte personal-stack evidence.

- CI is the gate for tap and profile pin bumps. `pi-harness-e2e`'s local `make verify` is retired by this gate, not a prerequisite for it. Owner-local installation/render checks belong to the dotfiles doctor (`PLAN.md` item 7)
- No default binary, home, credentials or package set. Inputs are `PI_BIN` and `--stack <file>`; the release fetcher accepts `--tag` or an initialized `--gitlink`. Nothing discovers the owner's Pi, dotfiles, tap or Brewfile
- Do not run real processes on the owner's swap-bound Mac. `make check-integration` runs formatter, linter, ty and infrastructure units only; CI owns scenarios

Inputs and installation:

```sh
cd integration
uv sync --locked
uv run --locked python -m harness.release --gitlink ../forks/pi --prefix /tmp/pi-candidate
# Or: --tag v1.3.0-nredd.7. Prefix must be empty, never a live install.
export PI_BIN=/tmp/pi-candidate/bin/pi
uv run --locked pytest scenarios/test_*.py scenarios/tui/test_footer_resize.py \
  --stack stacks/personal.json -m stack -n 2 --dist loadfile --log-cli-level=INFO
# Repeat with --stack stacks/local.json.
```

- `harness/release.py` copies the tap formula's recipe: global `npm install` of the released coding-agent tgz with Homebrew's `--build-from-source --ignore-scripts` defaults and the formula's `--min-release-age=0` override, replace its nested `@earendil-works/pi-tui` with the released tui tgz, remove foreign native prebuilds. It never reads the tap at runtime
- The exact Gitlink must have a release tag (`git describe --tags --exact-match`), not a nearest ancestor. `fetch_release` verifies EVERY asset the harness consumes: coding-agent, tui, `pi-agent-core` and `pi-ai`. New tags need all four in the release `SHA256SUMS` plus `gh attestation verify` provenance for each; legacy tags `.3`-`.7` use the frozen `LEGACY_CHECKSUMS` map (`.3`/`.7` shipped only coding-agent and tui). Only coding-agent and tui are installed; the other two are verified because the root `overrides` consume them. A missing or unrecorded asset, malformed or duplicate checksum, digest mismatch or failed provenance refuses installation before npm runs
- `python3 -m harness.release --verify-root-overrides --root <repo>` (with `PYTHONPATH=integration`; standard library only, no `uv sync`) verifies the root `package.json` core overrides against the lockfile `resolved`/sha512 and the release checksums (and provenance for non-legacy tags) before `npm ci`. See [releases](../docs/releases.md)
- Bun standalone: each OS's existing `stack (..., personal)` job builds the Gitlinked core using pinned `.bun-version`, frozen release model data and the official `scripts/build-binaries.sh --offline-model-data`. Each native OS build (darwin-arm64/macOS 14, baseline linux-x64/Ubuntu 24.04) is reused in that runner for sequential `personal` and `local` D/E runs with `--runtime bun-standalone`. `PI_BIN` points directly at the extracted standalone, not Node. No binaries are committed. Release `v1.3.0-nredd.7` still has only npm tarballs; source-build coverage does not prove a published standalone. Linux ARM64 is NOT RUN. Zero new jobs are added, including no new macOS runner; existing `local` cells add no work
- CI reports the binary's `--version` and exact tag; installation logs the stack document SHA-256 and each installed manifest name/version/source. Per-OS, per-stack artifacts retain failures and JUnit results
- `Stack` is a strict versioned Pydantic schema: `schema_version: 1`, `name`, exact `core` tag plus formula-consumed artifact SHA-256 values, nonempty ordered `sources`, harness-only `settings`, and reasoned `disabled_extensions`. Sources accept strings or Pi objects containing `source` plus optional `extensions`/`skills`/`prompts`/`themes` string arrays. Unknown object keys, null/non-array filters and non-string items are refused. Uniqueness and headless exclusions use the source string, including mixed string/object duplicates. npm versions and git refs are exact versions; local paths resolve relative to the stack file. Stack JSON forbids floats, lone surrogates, non-string object keys and integers outside JavaScript's safe-integer range at every depth: the dotfiles JavaScript consumer recomputes its digest, so settings values must use safe integers (±(2**53-1)), strings, bools, null, lists or objects. Unknown fields, implicit-home paths and a `settings.packages` override are refused. `uv run --locked python -m harness.stack_fixture` regenerates the shared canonical-byte fixture checked by both repositories
- `stacks/local.json` is derived from `personal.json` (`derive_local_stack`): owned npm identities map to `../../packages/*` (`OWNED_WORKSPACE_PATHS`: `@nredd/pi-todo` -> `packages/todo`, `@nredd/pi-subagents` -> `packages/subagents`, `@nredd/pi-plan-mode` -> `packages/plan-mode`, `@nredd/pi-computer-use` -> `packages/computer-use`), so local cells install the imported package directories. Order, `packageAgents` policy, filters and `disabled_extensions` are carried over unchanged. In-process tests load the same directories (`support.ts` `FORK_ENTRIES`). `forks/pi` is the only Gitlink still consumed
- Installation invokes `pi install <source>` for each source identity, then persists the declared object in `settings.json`'s `packages`. Filters are passed unchanged to Pi, not interpreted by the harness: omitted means manifest defaults, `[]` disables that resource kind, and `!`/`+`/`-` patterns retain Pi semantics. Headless exclusions override only `extensions` to `[]`; other object filters survive. `stack-evidence.json` records effective `configured_packages` as well as installed identities
- `personal.json` is the thirteen-source dotfiles selection: filtered `@nredd/pi-preset@0.2.0` first, then twelve exact npm sources in unchanged order (including `@gotgenes/pi-anthropic-auth@3.4.3`, which both stacks use). Full preset adoption is still deferred to profiles (#21). `0.2.0` is published, so `pi install` resolves it from npm; there is no skip, floating version or local-package substitution. The fixture policy sets `packageAgents: false` for any stack containing a filtered object source (`sandbox.subagents_policy`), so the rule follows content, not the stack name. For personal this matches dotfiles, which sets it unconditionally; `local` intentionally keeps package agents
- `personal.json` is the only maintained package array. `local.json` is a strict three-field derivation descriptor loaded by `harness.stack.load_stack`: it replaces owned npm identities with their workspace paths, moves the preset to the end, and adds that full unfiltered local preset. This preserves the existing local source order and resource-selection distinction without a second editable package list. CI therefore keeps the full-preset development coverage while personal proves the published footer-only selection
- Both stacks install `pi-computer-use` through Pi but explicitly disable its npm lifecycle scripts and extension discovery on both platforms. Its postinstall otherwise creates a GUI app even before extension loading, so the declared headless exclusion must cover that side effect too. macOS needs GUI/TCC and Linux has no CI desktop session. This is a declared headless exclusion, not coverage of its helper. Fork-owned desktop suites remain opt-in
- npm user/global configs are separate empty private files, never the owner's npm config or the same `/dev/null` loaded twice. Installer failures include captured command diagnostics
- Pi performs every package install into a new `PI_CODING_AGENT_DIR` and HOME. No package directory is linked from the owner's install. Per-test homes copy only that installed fixture; writable auth/session/cache/tmp/XDG state is private. Local package sources are deliberately the caller's supplied workspace
- The final package list uses the stack's resolved sources, not Pi's cwd-relative saved paths; this preserves declared exclusions when fixture homes are copied. Exact npm versions are checked against installed manifests
- Fixture-only deferred-tool, router and disabled workflow-trigger settings are explicit harness policy, not copied owner preferences. `subagents.json` sets `workflowsEnabled: false`: the separate dynamic-workflows package owns workflow orchestration, so the two do not produce a startup conflict warning. Titles are disabled unless a dedicated scenario enables a faux title model. No live credentials are inherited

Infrastructure:

- xdist `--dist loadfile` keeps each file's cases together; each worker installs its own immutable fixture input and each test gets private writable state. Kernel-assigned loopback ports, private tmux servers and exact worker-separated process tags prevent collisions
- Headless JSON drains stdout/stderr concurrently with size limits and a hard deadline, including silent-process failures. RPC has concurrent bounded readers and deadline-based event readiness. TUI launch failures clean up their private server; a wrapper records the child's actual exit status rather than relying on version-dependent tmux exit-status format fields. Before server teardown, `*.pane.json` records the native pane PID/dead/status/signal response (unsupported fields stay empty), wrapper status path and marker contents or absence. The existing failure-artifact allowlist retains that report and `*.exit`, not arbitrary JSON or the sandbox HOME. Startup text/JSON/RPC subprocesses stream original stderr bytes into `startup-<mode>.stderr` even on timeout/nonzero exit; the concurrent RPC driver also preserves raw stderr on timeout/early EOF within its existing 8 MiB limit. No exit assertion or deadline changes. Synthetic real-tmux proofs run explicitly with `uv run --locked pytest scenarios/tui/test_exit_evidence.py -m tui`; they require tmux but no Pi build or installed stack. Crash provenance and missing historical evidence are recorded [here](../docs/ci.md#startup-exit-failure-evidence)
- Auth transport first requires an in-process preload nonce, a refused non-loopback probe and a successful loopback readiness echo. Missing `NODE_OPTIONS` support fails startup before credentials can dispatch. It then uses only fake credentials and a Node preload guarding `fetch`: Anthropic/OAuth hosts redirect to the recording loopback server; other non-loopback fetches fail closed. Forbidden `claude`/`security` subprocesses are recorded/refused. Seven dispatch/refresh cases carry `node_preload`; `--runtime bun-standalone` explicitly skips them before fixtures, with a reason in pytest/JUnit. The missing-preload refusal runs on both runtimes. Auth interception remains NOT RUN on Bun pending #14 (old #58 references were stale). No other selected D/E scenario needs a preload or `--expose-gc`; the latter remains in excluded render benchmarks. Standalone packed contracts, live credentials, REA, desktop helpers and benchmarks remain outside this gate
- Auth wire assertions derive from `@gotgenes/pi-anthropic-auth@3.4.3`'s `src/{oauth-transport,billing-header,system-prompt-shaping,claude-code-version}.ts`: direct Anthropic and `router/default` OAuth carry Pi's native `claude-cli/X.Y.Z` user agent, bearer token and a leading billing system block with salted `cc_version`, `cc_entrypoint=sdk-cli` and first-user-text hash. The expected billing version is the numeric maximum of the recorded user-agent version and the bundled floor read from the sandbox's installed `src/claude-code-version.ts`, matching upstream's fetch-time synchronization without conflating the two versions. Today's pins both report `2.1.280`; the exact billing value remains checked. Pi's Claude Code identity remains; the neutral preamble and retained XML sections stay in `system[]`, docs/tools filler are removed, project context is preserved, and the user message stays `hi`. API-key and unconfigured custom-provider requests retain Pi's unshaped system prompt. The old fork's user-agent suffix and system-to-user relocation are no longer expected. Tool goldens are unchanged: the new extension adds a command, not tools.
- Coverage boundary: the wrapper applies to physical `anthropic` provider calls through model runtime, including virtual router resolution. Upstream documents compaction and `ctx.modelRegistry.streamSimple()` as covered, but this scenario does not test those paths. Explicit pi-ai `compat.streamSimple` calls and legacy agent loops omitting `streamFn` bypass it; additional provider names require the extension's explicit config. No API-registry override closes those gaps.
- Flakes follow [here](../docs/ci.md): correctness blocks, one fresh whole-job rerun only for an isolated documented flake, both attempts retained. No automatic retry-until-green
